== Performance considerations

=== Memory management

Moxml maintains a node registry to ensure consistent object mapping:

[source,ruby]
----
doc = context.parse(large_xml)
# Process document
doc = nil  # Allow garbage collection of document and registry
GC.start   # Force garbage collection if needed
----

=== Efficient querying

Use specific XPath expressions for better performance:

[source,ruby]
----
# More efficient - specific path
doc.xpath('//book/title')

# Less efficient - requires full document scan
doc.xpath('//title')

# Most efficient - direct child access
root.xpath('./*/title')
----


=== Run with YJIT

The wrapper layer is Ruby-dispatch-heavy — exactly what YJIT compiles
well. Enable it for any throughput-sensitive workload (Ruby >= 3.3;
production-ready since then):

[source,bash]
----
RUBY_YJIT_ENABLE=1 ruby your_app.rb   # or: ruby --yjit
----

Measured against raw engine calls on a 52KB fixture (leptris,
min-of-N, 100 warm reads): without YJIT the facade adds +23% on tree
walks and +43% on warm attribute reads; **with YJIT those become
-12% (faster than the binding's own walk) and +10%**, and `.name`
reads reach parity. Parse, serialize and duplicate are C-bound
either way. No semantic surface changes — it is a runtime flag.

Consumers on CRuby 3.3+ (canon's pretty-print pipeline, batch
conversion) should treat it as the default; moxml's own CI
performance gates run with YJIT enabled.

=== Wrapper retention — the identity map is weak

`Context` keeps a native→wrapper identity map so repeated traversals
hand back the same wrapper. Since 0.5.31 it is an
`ObjectSpace::WeakMap`: entries die with their native, so
parse-and-drop workloads release wrappers, natives, and (once the
binding's finalizer runs) the C subtrees. Measured walking and
dropping 220 documents (~600 elements each) with one long-lived
Context: **+1.9MB RSS growth vs +41MB before**, zero wrapper
retention beyond the binding's own constant one-document cache —
and no identity loss, which the previous 65,536-entry wholesale
clear traded away when it fired.

=== Lazy result sets

`xpath` results and `children` node sets allocate wrapper slots on
first access, not at construction — `.size`/`.empty?`/`.first` on a
1000-node result no longer allocate the 1000-slot wrapper array
(that path also skips the binding's per-node wrapper materialization
entirely; see `LazyNodeSet` under the leptris adapter).

=== Prefer bulk paths for per-node conversion

Per-node Ruby iteration pays the wrapper tax per element. When the
goal is conversion rather than manipulation, the bulk paths move the
loop into C: `materialize_fields` streams the flattened record
fields from one C call and measures faster than an equivalent
raw-Nokogiri DOM walk. See
link:conversion-apis[Conversion and memory lifecycle APIs].
