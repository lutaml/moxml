== Leptris adapter

Leptris is a pure-C99 XML 1.0 parser with an FFI binding (the
https://github.com/leptris/leptris-ruby[leptris-ruby] gem). It is the
preferred default on CRuby: fastest on every measured moxml operation,
with a native XPath 1.0 engine, SAX, and canonicalization.

== Default resolution

Leptris becomes the default when the installed binding meets the
adapter's floor — `Moxml::Adapter::Leptris::MINIMUM_BINDING_VERSION`
(leptris >= 1.9.32; issue #149): bounded traverse, built documents
that reflect their parts immediately, and every capability surface
the adapter assumes. Below the floor the default falls back to
Nokogiri rather than driving a binding the adapter no longer
accommodates. Under Opal the default is rexml (stock oga requires
its C extension and libleptris does not build for Opal).

[source,ruby]
----
Moxml.new                     # => Leptris context when capable
ctx.config.adapter_name        # => :leptris / :nokogiri / :rexml (Opal)
----

== Parse options

`noblanks: true`::
Drop whitespace-only text nodes — libxml2 `XML_PARSE_NOBLANKS`
semantics (issues #153/#156): boundary spaces of text-bearing
nodes survive. Implemented moxml-side (the engine flag trims
boundaries too — leptris/leptris/#677); requires a mutable
document, so `readonly: true` + `noblanks: true` raises.

`readonly: true`::
The binding memoizes every read and refuses mutations — the
parse-and-read lifecycle for multi-pass consumers (comparison, diff,
signatures). Repeat attribute reads on a large element drop by
orders of magnitude. Builder documents stay read-write.

`dtdattr: true`::
Materialize DTD `<!ATTLIST>` defaults. Off by default, matching
libxml2/Nokogiri/REXML semantics (libleptris >= 1.9.8).

`strict: true`::
Raise `Moxml::ParseError` on malformed input instead of returning an
empty document.

== HTML parsing

`Context#parse_html(html)` (leptris >= 1.9.80; engine
leptris/leptris/#659) parses tolerant HTML4/5 into the standard XML
DOM: implied end tags (`<li>a<li>b`), void elements (`<br>`, `<img>`),
raw-text script/style, case-insensitive lowercased names and
attributes, minimized/boolean attributes, and the HTML named-entity
table. `html`/`head`/`body` are synthesized when the input implies
them (no empty head for headless fragments); tables get no implied
`tbody`. Malformed input degrades to text — the parse never fails;
only an entirely empty result raises `Moxml::ParseError`.

[source,ruby]
----
doc = Moxml.new(:leptris).parse_html(%(<ul><li>a<li>b</ul>))
doc.xpath("//li").map(&:text)   # => ["a", "b"]
----

Serialization is XML-shaped: text content is escaped (`a &lt; b`),
so script bodies with markup characters round-trip through a strict
XML reparse. The adapter stands the entity-marker pipeline down for
HTML parses — the engine decodes HTML entities directly into text.

Adapters without an engine HTML mode (Ox, Oga, REXML, LibXML) raise
`Moxml::AdapterError`; Nokogiri parses through libxml2's HTML mode.

== Lifecycle

`Document#free` releases the C tree deterministically — batch
workloads parsing thousands of documents otherwise hold native memory
until GC finalizers run. Access after `#free` raises the binding's
use-after-free error.

== Document model

Documents expose the libxml2-shaped document node: prolog PIs and
comments, the root element, epilog PIs and comments, in document
order (leptris >= 1.9.26). The DOCTYPE round-trips with its internal
subset. See link:../conversion-apis[Conversion and memory lifecycle APIs]
for `materialize` — the flattened-record conversion path with a bulk
implementation over one `leptris_node_traverse` call.

== Known limitations (tracked upstream)

* Tab indentation honors the indent-unit string on leptris >= 1.9.45
  (`indent_text:`), byte-identical to Nokogiri including
  text-bearing children and comment children alike
  (leptris/leptris#658 at 1.9.46; leptris-ruby#115 at 1.9.50).
* A PI preceding the DOCTYPE reorders on serialization — libleptris
  normalizes DOCTYPE-first and the document node does not record its
  relative position.

Resolved with leptris-ruby 1.9.42 (leptris/leptris#636/#612): child
PIs serialize on their own indented lines, DOCTYPE internal subsets
newline-separate their declarations (moxml re-formats the subset to
the libxml2 layout), the stray trailing newline after non-ASCII
ending elements is gone engine-side, and document-level PIs accept
`target=`/`content=`/removal with full round-trip. The moxml-side
compat guards remain as no-ops for older floor bindings.
