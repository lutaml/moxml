== Advanced features

=== XPath querying and node mapping

==== Nokogiri, Oga, REXML, LibXML

Moxml provides efficient XPath querying by leveraging the native XML library's
implementation while maintaining consistent node mapping:

[source,ruby]
----
# Find all book elements
books = doc.xpath('//book')
# Returns Moxml::Element objects mapped to native nodes

# Find with namespaces
titles = doc.xpath('//dc:title',
  'dc' => 'http://purl.org/dc/elements/1.1/')

# Find first matching node
first_book = doc.at_xpath('//book')

# Chain queries
doc.xpath('//book').each do |book|
  # Each book is a mapped Moxml::Element
  title = book.at_xpath('.//title')
  puts "#{book['id']}: #{title.text}"
end
----

==== Ox

The native Ox's query method
https://www.ohler.com/ox/Ox/Element.html#method-i-locate[`locate`] resembles
XPath but has a different syntax.

==== HeadedOx

HeadedOx provides comprehensive (but not fully) XPath 1.0 support via a pure
Ruby XPath engine layered on top of Ox.


=== Namespace handling

[source,ruby]
----
# Add namespace to element
element.add_namespace('dc', 'http://purl.org/dc/elements/1.1/')

# Create element in namespace
title = doc.create_element('dc:title')
title.text = 'Document Title'

# Query with namespaces
doc.xpath('//dc:title',
  'dc' => 'http://purl.org/dc/elements/1.1/')
----

=== Accessing native implementation

While not typically needed, you can access the underlying XML library's nodes:

[source,ruby]
----
# Get native node
native_node = element.native

# Get adapter being used
adapter = element.context.config.adapter

# Create from native node
element = Moxml::Element.new(native_node, context)
----

=== Parse bookkeeping opt-outs (leptris)

Data-pipeline parses that never read diagnostics or source positions can
skip that bookkeeping. Both are opt-in per call; the default parse is
byte-identical either way.

[source,ruby]
----
# Duplicate attributes admit silently: queries answer first-wins, but
# the duplicate stays in the tree, so the serialized form can carry it.
doc = Moxml.new.parse(xml, skip_dup_detection: true)

# Source columns degrade; lines still resolve.
doc = Moxml.new.parse(xml, skip_source_positions: true)
----

Without the flags, a duplicate attribute records a recover diagnostic in
`doc.parse_diagnostics` and parses with the first value.

=== XSLT transformation (nokogiri, leptris)

Compile-once, apply-many transformations through an implementation-agnostic
interface. Engines: nokogiri (libxslt, XSLT 1.0) and leptris (XSLT 1.0-3.0
per its engine). Adapters without an engine raise
`Moxml::NotImplementedError` at compile; `Moxml::XSLT.supported?(context)`
answers without raising.

[source,ruby]
----
ctx = Moxml.new(:leptris)
sheet = ctx.xslt(<<~XSL)
  <xsl:stylesheet xmlns:xsl="http://www.w3.org/1999/XSL/Transform" version="1.0">
    <xsl:template match="/"><out><xsl:value-of select="count(//item)"/></out></xsl:template>
  </xsl:stylesheet>
XSL

result = sheet.apply_to(doc)          # Moxml::Document (same adapter)
text   = sheet.apply_to_string(doc)   # String — fragments and text output
----

`apply_to` raises `Moxml::XsltError` when the output method cannot produce
XML (method="text"); `apply_to_string` carries non-XML output. Documents
parsed by another adapter serialize through their own adapter and re-parse
into the engine. Top-level parameters are part of the contract
(`params: { "name" => "value" }`); leptris does not thread them yet
(leptris-ruby#360) and raises `Moxml::XsltError` when non-empty params are
passed.
